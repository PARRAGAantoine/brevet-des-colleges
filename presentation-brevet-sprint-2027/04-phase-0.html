Phase 0 — Cadrage

Création du site de préparation qui définit l’esprit, les règles et le plan du projet Brevet Sprint 2027 avant le lancement de l’application.

Objectif de cette phase

Avant d’écrire la moindre ligne de l’application élève, on construit un site de cadrage. Ce site sert de référence unique pour tous ceux qui travailleront sur le projet.

Il contient la présentation du projet, les règles immuables, les rôles, les skills des agents, la roadmap, l’architecture fichiers et le catalogue des 88 cours. On fige les skills en même temps que les règles et les templates. Tout le cadrage est prêt avant de produire. Tant que ce site n’est pas validé, on ne commence pas le développement de l’app.

Ce que ce site doit contenir

  • 00 — Présentation : pourquoi l’app existe, pour qui, les règles qui font la différence, le Mode Aventure.
  • 01 — Instructions : stack technique, interdits, budget 0 €, nommage des fichiers, contact réel.
  • 02 — Rôles : les agents et leurs skills (chef, design, cours, exo, test, tech). Fichiers skill_[nom].md figés ici.
  • 03 — Roadmap : les 7 phases, les principes, les livrables et critères de sortie.
  • 04 à 10 — Détail des phases : une page par phase avec les attendus concrets.
  • 12 — Catalogue : les 88 cours répartis en 4 matières.
  • 13 — Architecture : arborescence fichiers, sans accents, Annales hébergées.
  • Index : point d’entrée clair pour naviguer dans tout le cadrage.

Création des skills (fichiers .md)

Chaque agent a un fichier skill_[nom].md (ex. : skill_cours.md, skill_exo.md). Ces fichiers sont rédigés et figés en Phase 0.

Structure optimale d’un skill

  • Nom et rôle — une ligne claire (ex. : « cours — Créateur de cours »)
  • Mission — ce que l’agent doit accomplir, en 1 ou 2 phrases
  • Entrées — ce qu’il reçoit (ex. : titre du cours, matière, niveau)
  • Sorties — ce qu’il produit (ex. : page HTML complète du cours)
  • Règles immuables — contraintes qu’il ne doit jamais enfreindre (vocabulaire simple, template 9 sections, bouton « J’ai fini de lire », etc.)
  • Format attendu — structure exacte du livrable
  • Exemple copier-coller — un mini-exemple concret prêt à réutiliser
  • Critère de validation — comment savoir que le travail est bon (ex. : passe le test ELEVE_TEST)

Principes d’écriture

  • Court et actionnable : un skill se lit en moins de 2 minutes
  • Pas de jargon inutile
  • Chaque règle est testable
  • L’exemple doit pouvoir être copié-collé directement
  • On commence par skill_cours.md et skill_exo.md (les plus critiques)

Règles de travail pendant cette phase

  • On ne code pas encore l’application élève.
  • On reste en HTML/CSS simple, même style sombre #0d1418.
  • Chaque page du site de cadrage doit être claire, courte et actionnable.
  • Les décisions prises ici (bouton « J’ai fini de lire », aide à 2 niveaux, dark only, localStorage, badges, etc.) deviennent des règles immuables pour la suite.
  • Les skills sont figés ici, avant toute production de contenu.
  • La phase 0 ne passe en TERMINÉ que sur feu vert explicite.

Checklist de fin de phase

  • Index clair avec liens vers toutes les pages
  • Présentation (00) rédigée
  • Instructions (01) rédigées
  • Rôles (02) définis
  • Skills des 6 agents figés (skill_[nom].md)
  • Roadmap (03) en 7 phases validée
  • Pages de détail des phases 0 à 6 complètes
  • Catalogue (12) à jour
  • Architecture (13) à jour
  • Cohérence visuelle sur toutes les pages
  • Aucun lien cassé
  • Feu vert final donné
Livrable de sortie : un site de cadrage complet, cohérent et validé, qui sert de référence unique avant de commencer la Phase 1 (templates + premiers contenus de l’application élève).
